# 独立企业知识助手设计

**状态：** 已于 2026-08-15 在对话中分段确认通过

**产品名称：** 企业知识助手

**关联设计：**

- `2026-08-12-yuxi-feishu-knowledge-platform-integration-design.md`
- `2026-08-12-chat-workspace-layout-design.md`

**文档效力：** 本文补充并修正上述设计的普通用户问答入口。与旧设计冲突时，以本文为准；其中最重要的变更是取消普通用户的“回答范围”选择器，并禁止把 Yuxi 原生 Agent 页面作为产品入口。

## 1. 背景与纠偏

当前部署在 `http://localhost:5175/agent` 的页面是 Yuxi 原生 Agent 界面。它要求用户理解智能体、模型和 `@知识库` 等技术概念，不适合作为普通员工的知识问答入口。

现有 `KnowledgeBase` 工程已经包含独立 React 问答页，具备历史会话、底部固定输入框、资料上传和来源抽屉等产品结构，但其正式后端尚未迁移完成：当前仍连接 Fastify、本地 JSON、确定性 AI 和本地词法检索。`KnowledgeBase-Yuxi` 当前分支已经具备模型调用、知识库检索、飞书扫描、审核和发布能力，但尚未提供独立产品问答所需的 FastAPI 会话接口、飞书用户登录和临时资料联合分析接口。

本设计修正最终入口：普通用户使用独立 React“企业知识助手”；Yuxi Vue 只供技术管理员配置和诊断，不作为普通用户入口。

## 2. 目标与完成边界

普通员工通过飞书登录后直接进入独立问答页，在输入框中使用自然语言提问。系统在后台自动选择企业正式知识，返回有依据、可追溯的答案，不要求用户选择模型、智能体、知识库或输入 `@`。

本次建设拆成两个可独立验收的阶段：

1. **企业知识问答闭环：** 飞书登录、个人会话、自动检索唯一企业知识库、精准回答、结论状态和飞书来源引用。
2. **个人资料联合分析：** 安全上传、临时解析和索引、自动结合企业知识、双来源引用以及到期清理。

阶段 1 完成后可以独立上线，不等待阶段 2。阶段 2 不改变阶段 1 的提问方式。

本设计不包含：

- 重做飞书扫描和知识加工工作台。
- 让普通用户访问 Yuxi 原生 Agent 页面。
- 向普通用户暴露模型、Embedding、Top-K、Chunk、提示词或知识库 ID。
- 音视频资料加工。
- 多企业租户、知识图谱、本地模型和自动文档排版。
- 扩建新的原子知识治理流程；当前以知识加工工作台审核并发布到目标 Yuxi 知识库的内容作为正式问答语料。

## 3. 已确认决策

1. 采用现有 React 界面作为唯一普通用户入口。
2. 产品名称使用“企业知识助手”。
3. 页面采用左侧历史会话、中间问答、右侧按需展示来源的工作台布局。
4. 输入框固定在对话区底部，只有消息区域滚动。
5. 无附件时自动使用企业正式知识。
6. 上传资料后自动使用“个人资料 + 企业知识”，不显示范围选择器。
7. 普通员工使用飞书 OAuth 登录；后台扫描继续使用企业自建应用的 `tenant_access_token`。
8. Yuxi Vue、知识加工工作台和模型配置仅对管理员开放。
9. 没有足够正式依据时明确回答“暂无足够可靠资料”，不得用模型常识补成企业承诺。

## 4. 系统架构

```text
普通员工                           管理员
   |                                 |
   v                                 v
独立 React 企业知识助手       知识加工工作台 / Yuxi Vue
   |                                 |
   +---------------+-----------------+
                   |
                   v
             统一 FastAPI
       |-- 飞书 OAuth 与产品会话
       |-- 对话与临时资料
       |-- 权限过滤与知识检索
       |-- 受约束回答与引用
       `-- 飞书扫描、审核与发布
                   |
      +------------+-------------+-------------+
      |            |             |             |
 PostgreSQL      MinIO         Milvus        Redis
 业务与会话    原文与附件     检索索引      任务与事件
```

React 只调用稳定的产品 API，不直接调用 Yuxi 原生聊天页面，也不在前端拼装 Agent、Skill 或 `@knowledge` 指令。FastAPI 内部复用 Yuxi 的模型、解析和知识检索能力。

PostgreSQL 是对话、消息、身份映射、引用和临时资料状态的唯一业务真相。MinIO 保存原文件和解析产物，Milvus 保存可重建检索表示，Redis 只承担任务和事件。

## 5. 身份与权限

### 5.1 两类飞书凭据

- **用户 OAuth：** 识别具体员工、建立个人会话、保护历史记录和临时资料，并参与知识访问权限判断。
- **企业 `tenant_access_token`：** 后台读取已授权飞书目录、页面和附件，用于扫描和知识加工。

二者不可互相替代。后台应用能够读取资料，不代表任意登录员工都有权在问答中看到该资料。

### 5.2 登录流程

1. 未登录用户访问产品入口时跳转到简洁登录页。
2. 用户点击“使用飞书登录”。
3. FastAPI 生成带有效期的一次性 `state`，发起飞书 OAuth。
4. 回调成功后保存飞书用户标识和组织映射，签发 HttpOnly 会话 Cookie。
5. 用户进入 `/chat`，加载自己的历史会话。
6. 登录失败、回调过期或身份映射失败时不创建会话，并提供重新登录入口。

### 5.3 权限原则

- 检索前先计算当前用户可访问的来源或策略范围，再调用 Milvus。
- 打开企业引用时再次校验当前权限。
- 无法确认权限时默认拒绝，不沿用可能过期的缓存结果。
- 普通用户不能进入知识加工和 Yuxi 技术路由。
- 管理员也不能因为角色较高而绕过具体知识的来源权限。

## 6. 普通用户页面

### 6.1 页面结构

顶部只显示产品名称和当前用户。主体是全高工作区：

1. 左侧为新建对话和历史会话列表。
2. 中间为会话标题、消息内容和底部输入区。
3. 右侧来源抽屉只在用户点击引用时出现。

普通用户页面不显示 Knowledge Factory、Yuxi、模型名称、智能体、Skill、知识库选择或技术参数。

### 6.2 输入区

- 输入区位于对话区网格最后一行，不使用相对浏览器窗口的固定定位。
- 消息变长时只滚动消息区，输入区始终可见。
- 默认只显示问题输入、上传资料按钮和发送按钮。
- 阶段 1 尚未交付资料上传时不显示上传按钮；阶段 2 上线后再启用该入口。
- 无附件时后台自动选择企业知识。
- 上传资料就绪后显示“自动结合当前资料与企业知识”，不要求用户手动切换范围。
- 资料仍在处理或处理失败时不得参与回答。

### 6.3 回答与引用

每个回答包含：

- 回答正文。
- `SUPPORTED`、`INSUFFICIENT` 或 `CONFLICTING` 结论状态对应的中文提示。
- 使用的企业正式知识引用。
- 使用个人资料时的需求来源引用。

需求来源和企业依据使用不同标签。企业依据展示正式知识标题、原始飞书文档、目录位置、段落或页码和版本时间；需求来源展示附件名称以及页码、章节或段落。桌面端来源在右侧抽屉显示，手机端使用全宽覆盖抽屉。

## 7. 问答数据流

### 7.1 企业知识问答

```text
用户问题
  -> 校验登录和会话归属
  -> 读取后台绑定的目标企业知识库
  -> 计算当前用户允许访问的知识范围
  -> 在允许范围内执行混合检索
  -> 校验检索结果仍处于已审核、已发布、索引有效状态
  -> 使用检索证据生成受约束回答
  -> 保存消息、结论状态、版本和引用
  -> 返回正文与可点击来源
```

目标知识库由管理员配置并与飞书知识数据源绑定，前端请求不接受任意知识库 ID。当前目标沿用知识加工工作台的数据源配置，后续修改链接或目标库时只调整管理员配置。

### 7.2 个人资料联合分析

```text
上传资料
  -> 校验类型、大小和文件安全
  -> 绑定当前用户和当前会话
  -> 写入 MinIO 并调用 Yuxi 解析
  -> 写入独立临时索引
  -> 标记就绪

用户任务指令
  + 当前会话资料
  + 当前用户可访问的企业正式知识
  -> 识别需求与约束
  -> 逐条检索企业依据
  -> 生成满足 / 部分满足 / 不满足 / 依据不足结果
  -> 返回需求来源与企业依据
```

个人资料只能证明用户提供了某项要求或背景，不能证明企业具备某项能力。只有已审核发布的企业知识可以作为企业能力依据。

### 7.3 临时资料生命周期

- 临时资料只允许当前用户在当前会话中访问。
- 默认 24 小时后删除原文件、解析正文和临时索引。
- 用户可以提前删除，删除后立即停止参与新回答。
- 历史消息可以保留，但过期资料不能再次打开或重新参与推理。
- 临时资料不得自动进入飞书目录或企业知识库。
- 阶段 2 支持 PDF、DOCX、PPTX、XLSX、TXT、Markdown、PNG、JPEG 和 WebP，单文件上限 100 MiB；宏文档、脚本和压缩包不在支持范围内。

## 8. 产品 API 边界

FastAPI 提供面向 React 的稳定接口，内部再适配 Yuxi：

```text
GET  /api/auth/feishu/login
GET  /api/auth/feishu/callback
POST /api/auth/logout
GET  /api/session

GET  /api/chat/conversations
POST /api/chat/conversations
GET  /api/chat/conversations/{conversation_id}
POST /api/chat/conversations/{conversation_id}/messages
POST /api/chat/conversations/{conversation_id}/archive

POST   /api/chat/conversations/{conversation_id}/attachments
DELETE /api/chat/conversations/{conversation_id}/attachments/{attachment_id}
GET    /api/citations/{citation_id}
```

阶段 1 实现认证、会话、消息和企业引用接口。阶段 2 增加附件接口、需求来源引用和附件清理任务。

前端消息请求只提交问题和当前会话 ID，不提交模型、Agent、知识库 ID、Top-K 或提示词。服务器从数据源配置中解析目标知识库，并记录实际使用的知识版本、模型版本和提示版本。

## 9. 核心数据

阶段 1 至少持久化：

- `product_conversations`：所有者、标题、状态和时间。
- `product_messages`：角色、正文、回答状态、模型与提示版本。
- `message_citations`：企业知识版本、飞书来源、定位和摘录。
- `feishu_user_bindings`：产品用户与飞书用户、部门和授权状态的映射。

阶段 2 增加：

- `session_assets`：所有者、会话、对象位置、解析状态和到期时间。
- 需求来源类型的 `message_citations`。
- 临时解析、索引和删除任务状态。

所有消息和引用都保存回答当时使用的正式知识版本。重新打开企业引用时仍需按当前权限重新校验。

## 10. 异常处理

| 状态 | 用户可见行为 | 系统行为 |
| --- | --- | --- |
| 依据充分 | 给出直接答案和来源 | 保存 `SUPPORTED` 和实际知识版本 |
| 依据不足 | 显示“暂无足够可靠资料”并说明缺口 | 保存 `INSUFFICIENT`，不补用模型常识 |
| 资料冲突 | 展示冲突结论、条件和各自来源 | 保存 `CONFLICTING`，不擅自裁决 |
| 权限无法确认 | 提示暂时无法确认访问权限 | 停止受保护内容检索和生成 |
| 知识服务异常 | 保留问题并提供重试 | 不暴露堆栈、模型错误和敏感配置 |
| 上传失败 | 展示文件、失败原因和重试入口 | 失败资料不参与回答、不进入企业知识库 |

发送中、归档中、附件处理中或会话切换中，沿用统一操作锁定，防止重复提交和跨会话串写。请求失败后保留用户尚未发送成功的文本。

## 11. 安全要求

- OAuth `state` 一次性使用并校验有效期；会话 Cookie 使用 HttpOnly 和 SameSite。
- 日志不得记录 OAuth code、access token、Cookie、用户问题全文、附件正文或引用摘录。
- 上传文件属于不可信输入，拒绝宏、脚本、路径穿越、超限和危险压缩包。
- 附件正文不能修改系统规则、触发未授权工具或扩大检索范围。
- 检索权限过滤发生在召回前，引用打开时再次校验。
- 服务器错误统一返回稳定错误码和可展示中文消息。

## 12. 测试与验收

### 12.1 自动化测试

- 飞书 OAuth 的成功、拒绝、过期 `state`、重复回调和身份映射失败。
- 未登录访问拦截、会话归属和跨用户隔离。
- 前端请求不包含知识库、模型、Agent 或 `@` 指令。
- 服务器始终使用管理员绑定的目标企业知识库。
- `SUPPORTED`、`INSUFFICIENT` 和 `CONFLICTING` 三种回答状态。
- 未审核、未发布、索引失败和来源失效内容不能参与回答。
- 权限服务异常时默认拒绝。
- 企业引用能够解析到正确飞书来源并重新校验权限。
- 阶段 2 覆盖附件类型、大小、安全、会话隔离、到期和删除。
- API 或 Worker 重启后，会话、消息和未完成任务不会丢失。

### 12.2 浏览器验收

在桌面、平板和手机视口验证：

- 飞书登录后直接进入“企业知识助手”。
- 页面不存在 Yuxi、模型、智能体、Skill、知识库选择和 `@` 操作。
- 用户可以新建、切换和归档自己的会话。
- 长回答只滚动消息区，输入框始终位于对话区底部。
- 来源抽屉可打开、关闭并跳转到有权访问的飞书原文。
- 未知问题返回依据不足，不生成虚构企业能力。
- 阶段 2 中，上传处理中不能误用未就绪资料，双来源标签清晰可区分。
- 页面无横向溢出、遮挡和新增控制台错误。

### 12.3 真实链路验收

使用已发布到当前目标知识库的飞书页面完成：

1. 一个可以由正式知识回答的问题。
2. 一个正式知识中没有答案的问题。
3. 一个引用能够回到飞书原文的问题。
4. 一个无权限用户不能召回或打开来源的问题。
5. 阶段 2 使用一份需求文件完成“要求识别 + 企业能力核对 + 双来源引用”。

不得在验收记录中保存真实凭据或复制企业文档正文。

## 13. 完成标准

### 阶段 1

- 普通用户通过飞书登录进入独立 React 问答页。
- 用户无需任何技术选择即可提问。
- 系统只依据当前用户有权访问、已审核、已发布且索引有效的企业知识回答。
- 回答状态、企业引用和飞书原文链路正确。
- 相关自动测试、类型检查、生产构建和真实浏览器验收全部通过。
- Yuxi 原生 Agent 页面不再作为普通用户入口，但继续保留给技术管理员。

### 阶段 2

- 用户能够上传当前任务资料并自动与企业知识联合分析。
- 个人资料和企业知识使用不同来源类型，且各自权限正确。
- 临时资料隔离、删除和 24 小时到期清理通过自动化与真实浏览器验收。

## 14. 当前实现差距

以下内容已经存在，可以复用：

- React 问答工作台布局、历史会话、消息线程、底部输入区和来源抽屉。
- Yuxi 模型调用、知识库检索、文档解析和基础聊天能力。
- 飞书企业自建应用认证、知识源扫描、审核和发布到目标知识库。

以下内容仍需实现：

- React 页面从旧 Fastify 契约迁移到统一 FastAPI 产品接口。
- 飞书用户 OAuth 登录、身份绑定和前端路由守卫。
- PostgreSQL 产品会话、消息和引用持久化。
- 后台自动绑定目标知识库并调用 Yuxi 检索、生成和引用能力。
- 当前用户的知识访问权限过滤与引用二次校验。
- 阶段 2 的安全上传、临时解析、索引、联合推理和过期清理。
- 独立产品入口的部署、健康检查和正式切换。

这意味着当前 `http://localhost:5175/agent` 只能用于验证 Yuxi 技术能力，不能作为本设计的产品验收入口。
